# Local independent LEAN pilot

This standalone CLI harness runs the open-source engine directly, without a paid CLI subscription, brokerage login, or purchased data. Standalone runs keep inputs, caches, SDK, source checkout and native results under ignored `output/lean-pilot/`. The integrated UI adapter described below additionally publishes immutable linked results into the local research store.

## Reproduce on Windows

Prerequisites: Git, the existing EOD Python environment, and the frozen local database configured for that service. Obtain .NET SDK **10.0.400** using Microsoft's official `dotnet-install.ps1`, installed in `output/lean-pilot/dotnet` with `-NoPath`. The pilot used [Microsoft's installer](https://dot.net/v1/dotnet-install.ps1). Do not copy provider credentials into LEAN configuration.

From the repository root:

```powershell
git clone https://github.com/QuantConnect/Lean.git output/lean-pilot/Lean
git -C output/lean-pilot/Lean checkout 23b735d99a357807dc0df9f4c51d30f05fe0d277
output/lean-pilot/dotnet/dotnet.exe build output/lean-pilot/Lean/Launcher/QuantConnect.Lean.Launcher.csproj -c Release -m:2
output/lean-pilot/dotnet/dotnet.exe build scripts/lean-pilot/PilotAlgorithm.csproj
```

From `services/eod`, choose a **fresh** output directory for cold-cache measurements:

```powershell
.venv/Scripts/python.exe -m brontide_eod.research_pilot --output ../../output/lean-pilot/reproduction
```

Then from the root:

```powershell
services/eod/.venv/Scripts/python.exe scripts/lean-pilot/run.py --evidence output/lean-pilot/reproduction --case all
services/eod/.venv/Scripts/python.exe scripts/lean-pilot/compare.py output/lean-pilot/reproduction
services/eod/.venv/Scripts/python.exe scripts/lean-pilot/catalog-report.py
```

`run.py` checks the pinned Git revision and freshness of each output. `compare.py` fails on unmatched signal identities, ATR, statuses, unexplained net-R arithmetic, missing bar processing, hand-statistic failures, or changed earlier checkpoints after future perturbation. Native price/timing/fee differences are explicitly retained, not patched into a custom fill simulator.

Each synthetic case has one independent position in a separate engine process. The real sample has no qualifying positions. This avoids claiming parity between LEAN's netted account and Brontide's independent-trade ledger; overlapping real trades would require separate per-trade replays before comparison.

## Data and time conventions

Real test: August 5–September 3, 2026, with earlier frozen bars back to January 2, 2024 for warm-up. Symbols are selected by SHA256 over `['lean-pilot-1', symbol]`, taking the smallest 20 hashes in the frozen universe, independent of results. No replacement of missing symbols or outcome-driven resampling.

CSV events contain opening price only at 09:30 America/New_York, and full daily OHLCV at 16:00. No fill-forward. Session ordinals come from the saved calendar, so gaps reset features and prohibit delayed entries. The daily feed does not prove half-day exchange timing or intraday path. It uses pre-adjusted provider bars; splits, dividends, delistings, point-in-time universe membership and data revisions remain unvalidated. The synthetic weekday calendar is an explicit test calendar rather than a claim about US holidays.

LEAN uses its native market/stop/limit handlers and brokerage tick rounding, with a declared 10-bps security-price fee model. Brontide uses 10 bps of entry/exit fill price per side, zero added slippage. There are no portfolio performance claims: cash is merely ample execution-harness capacity. The report's normalized TradeStatistics input is separate from the account statistics generated by LEAN.

## Integrated local comparison

The local Research Runs UI now supports optional LEAN comparison for the saved EP-2x-rvol95 pilot dated November 12–December 11, 2025. See `docs/RESEARCH_DUAL_ENGINE.md` for job endpoints, immutable artifacts, restart behavior and results. The current engine remains the default.

The adapter runs independent signal discovery and then one separate native account per signal. `execute_only` in a case's settings can be `none`, `*` (the original fixture default), or `SYMBOL/YYYY-MM-DD`. This controls order submission only; signal calculation stays independent.

Run the overlap regression with the service Python environment:

```powershell
services/eod/.venv/Scripts/python.exe scripts/lean-pilot/validate-overlap.py
```
